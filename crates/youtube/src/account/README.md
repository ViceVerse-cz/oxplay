# Account adapter and security boundary

This is implemented Rust code, with synthetic tests only. No live cookie, real Google identity, private account read, or remote account mutation has been used to validate it. The account acceptance gates remain open until an explicitly authorized local human test verifies the actual response shapes, displayed identity, private collections, outcomes, sign-out, and non-Premium ad behavior.

## Interface and ownership

Create `AccountClient` on a dedicated worker with a cloneable `SessionControl`. The provider is owned by that worker. The UI may immediately call `SessionControl::invalidate()` on account switching/sign-out; in-flight HTTP and extraction observe the changed generation and stop. Then the worker calls `disconnect()` to destroy the retained candidate/session and pending mutation. `disconnect()` does not advance a generation already invalidated by the UI a second time.

Parse only an explicit user-selected export using `SessionCookies::import_netscape(Zeroizing<Vec<u8>>, unix_seconds)`. The caller owns the bounded file read; this module never opens a browser profile. Import retains only allowlisted YouTube session cookies, with a 4 MiB/10,000-entry ceiling, strict Netscape fields, expiry/domain/path/secure rules, duplicate rejection, bounded cookie values, and redacted formatting. Candidate credentials are not a connected account.

`connect(cookies, account_index, operation)` performs the real `account/accounts_list` request and requires exactly one selected, enabled identity in the response. `ConnectionInfo` contains names/handles for UI display and separate capabilities. Unknown/no identity is an error. Nonzero account slots can be explicitly verified for reads; delegated-channel switching has no implemented safe selector and is reported unsupported.

The caller may explicitly pass `export_for_vault()` to the protected storage adapter only after identity verification. Vault decryption still requires fresh `connect()` verification before account capabilities return. Expired/rejected sessions lose connection/capability visibility and cannot be exported for persistence. Secret values use zeroizing allocations, but request libraries and operating systems can make temporary copies; no forensic-erasure guarantee is made.

## Requests, reads and writes

InnerTube requests are restricted to enumerated endpoints on `https://www.youtube.com/youtubei/v1/`. Cookie and SAPISID-derived authorization headers are sensitive/redacted and never attach to media/CDN requests. Redirects and ambient proxies are disabled. The inspected reqwest 0.12.28 default can retry protocol-level failures, so this client explicitly uses `reqwest::retry::never()`; no account write is retried automatically. There is a 30-second request timeout, 10-second connection timeout, 8 MiB response bound, and 20 ms cancellation checks while I/O is pending. No periodic task runs while idle. HTTP 429 and server Retry-After hints establish a monotonic cooldown (minimum 60 seconds); numeric and HTTP-date hints are honored. The HTTP client never retries a write. HTTP 5xx is treated as an unknown mutation outcome requiring reconciliation. Extractor rate-limit failures likewise impose a conservative 60-second local cooldown; yt-dlp does not expose structured server Retry-After headers to this adapter.

Subscriptions, account playlists, playlist contents, and the signed-in Home recommendation feed (`FEwhat_to_watch`, normalized to `VideoSummary` with promoted items and Shorts excluded) are paginated and normalized into typed models. Legacy renderer and reviewed modern lockup shapes are recognized. Each page is bounded to 200 items and traversal to 50,000 JSON nodes. Unknown pages cannot become a fabricated successful empty page. Continuation tokens are opaque and bound to collection kind/session generation. Provider-designated promoted shapes are excluded.

`apply_user_mutation()` is only for an explicit user action; import, connecting and reading never call it. Subscription and rating changes send one request and then reread state. Playlist modifications first verify editability and collect bounded item identities; addition reconciliation requires a new `setVideoId`, and removal checks the specific set item rather than assuming video IDs are unique. A maximum 25 pages / 2,000 items bounds a reconciliation snapshot. Missing item identities or unsupported state renderers fail conservatively.

A write timeout/network ambiguity returns `NeedsReconciliation` and retains a pending operation. Another mutation is blocked until `reconcile_pending()` observes the requested remote state. HTTP 200 alone does not prove success. A read-only human validation session is not permission to exercise these mutation methods.

## Explicit authenticated extraction

Public playback remains on the guest resolver. Only a deliberate authenticated-playback action should call `AccountClient::resolve_authenticated()`; importing cookies does not authorize automatic escalation. It requires a verified, unexpired generation and returns `AuthorizedPlayback { playback, authorization }`, with `playback.guest=false` and a nonsecret revocable `AccountPlaybackLease`. The policy-aware variant accepts an explicit `ResolutionPolicy`; see [account media boundaries](../../../../docs/account-media.md).

The inspected yt-dlp derives session/channel identity from imported web cookies; no safe account-index override was established. Authenticated extraction therefore fails closed for nonzero account slots or multiple available identities. This limitation must be visible rather than using a different account silently.

On Unix, each extractor job gets a randomized application-owned 0700 directory and a 0600 filtered Netscape file. Raw cookies never enter command arguments; only the private file path is passed through the verified `--cookies` option. Browser import, inherited configuration/plugins, remote challenge downloads, and implicit watched reporting remain disabled. The extractor may update that private jar, as documented by its CLI and inspected cookie-save implementation. The supervisor checks operation cancellation and account generation, kills the owned process group, and reaps the direct child before the jar is deleted. Explicit cleanup failures are errors. Windows authenticated extraction remains unavailable with the unimplemented job-object supervisor.

Call `cleanup_stale_extractor_sessions()` on an application worker at launch. It inspects at most 1,000 known app-owned directories, never reads cookie contents, never follows child symlinks, and only removes known private jars older than one hour. Normal jobs have a 45-second limit. Unknown contents are left untouched rather than traversed recursively. Abrupt power/process failure can leave a private temporary jar until cleanup; deletion is not forensic erasure.

The native media consumer must enforce the lease throughout open, redirects, I/O and cached reads; account playback integration and human validation remain separate gates. Successful authenticated extraction alone must not advertise verified authenticated playback, correct identity propagation, or account ad suppression. No cookies are placed into `MediaTrack.headers`.
