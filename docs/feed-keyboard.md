# Virtualized feed keyboard focus

The initial implementation compiled in checkpoint `0f311dd` (284 workspace Rust tests, 112 Python tests and strict Clippy passed), but its first native keyboard run failed. The corrected deferred-delivery implementation passed the complete diagnostic in both debug and release at `ca21de92a94abf209b76576c8b584751d3d20b4f`; see the retained results below. This does not qualify a screen reader or another platform.

The pinned Slint revision `cf3b07d4917e6759a63b0c03913a2594ec653414` reveals a focused instantiated item through `WindowInner::publish_focus_item` and `ItemRc::try_scroll_into_visible`. However, focus traversal obtains repeated siblings through `Repeater::instance_at`, which only returns currently instantiated rows. `update_visible_instances` fills the viewport and removes offscreen instances. Revealing the last existing card can still leave the next group below the viewport, so default Tab traversal can exit the feed before reaching the rest of its bounded page. The plain `ListView` supplies no arrow/page-key navigation; `StandardListView` implements that explicitly.

`feed_focus.rs` adds one identity-scoped handoff for the existing grouped feed. Tab and Shift-Tab move through the bounded logical page; arrows move between cards/rows, Page Up/Down move by viewport rows, and Home/End reach page boundaries. Tab at either edge leaves the feed normally. The adapter scrolls to the target group and briefly parks focus on one persistent, non-Tab scope while its target card becomes available. Only the matching item kind, ID, flat index and request serial may claim that handoff. Actual card FocusScopes and accessible buttons remain in use; no absolute row number is passed as an AccessKit descendant index.

Existing instances report readiness on a changed request; new repeated instances report it in `init`. The pinned `RepeatedItemTree` contract runs init after model update but **before** the outer group's `listview_layout` assigns its y position. Readiness therefore schedules one shared, coalesced single-shot timer; it does not focus during construction. After the layout stack unwinds, a separate delivery serial permits the matching card to claim focus. Cancellation stops that timer. Before column regrouping destroys old row instances, the adapter parks focus and retains the item identity, then reveals/restores that item in its new group. Ordinary thumbnail row updates do not regroup or reassign focus. The handoff adds no catalog rows, model resets, periodic timers or unbounded instance cache.

Loss of the parking scope to unrelated controls cancels the request. A deliberately claimed parking-to-card transfer is distinguished from that cancellation. Rapid navigation keys are coalesced by the parked scope from the pending logical index, without requiring a frame or a card instance between keys. Other native key/pointer/IME input and window deactivation invalidate older pending construction before Slint dispatches the new input. Leaving the browse page and replacing an acknowledged model explicitly retire pending/current identity; correctness does not depend on a destroyed card emitting focus-lost. Restoration requires the real window to be focused. An old completion cannot consume a newer request.

Pure tests cover every item in pages of 1/20/100/120 rows, leaving the feed at either Tab edge, bounded arrow/page destinations, stale identity/serial rejection, rapid coalesced navigation, outside-focus cancellation, explicit model replacement and old-card destruction during a deliberate resize transfer. The corrected source adds a readiness-versus-claim regression; the central workspace suite passed. The offline library-resource diagnostic exercises first card, End to actual acknowledged item 99 with immediate Left/Right while delivery is pending, Tab out and back, a column-changing resize retaining item 99, Home, Page Down, and cancellation by search focus before delivery. It requires the expected thumbnail to intersect the actual feed viewport as well as matching the latest focus callback, and logs finite handoff state for diagnosis.

The preserved first native failure is `artifacts/raster-native-v1/library.log`: all five real 100-row page/hover checks passed with six intersecting thumbnails and nine near-viewport images, then the 32-second assertion that End left a deferred offscreen target failed. That log did not record the parking/target values, so it cannot distinguish the final focus values. The pinned source identifies the synchronous construction path: `WindowInner::process_key_input` calls `ensure_tree_instantiated()` immediately after an accepted key handler, before dispatch returns (`window.rs:1350–1358`). End is accepted by the card, changes the viewport, then that instantiation pass can create the target and run the old immediate-focus `init` path within the same dispatch call. Therefore “no event-loop turn” never guaranteed deferred focus. Focusing before outer-row layout additionally risks automatic reveal using its earlier/default position. The correction makes delivery explicitly deferred and preserves the rapid-navigation assertion; it does not treat that failed run as keyboard success.
