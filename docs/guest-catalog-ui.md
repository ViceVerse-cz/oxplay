# Guest catalog UI integration

`crates/app/src/guest_ui.rs` adapts the provider's typed `CatalogItem` values directly into the shared Slint card model. It does not invent video records for channels or playlists. The existing supervised catalog worker handles all guest jobs and rejects replaced/stale results through its request generation and cancellation token.

The shared search filter exposes all results, videos, channels, and playlists. Video cards resolve a content stream; channel cards open the canonical public channel with videos/shorts/streams/playlists tabs; playlist cards open public playlist contents. Pasted canonical channel URLs and playlist URLs route to the same typed requests. A watch URL remains a video action even when it also includes a playlist query parameter. Channel handles are not yet resolved. Account connection does not change these requests from guest mode. A channel page enables “Follow locally” only after receiving real typed channel header metadata; the action uses the bounded local-library worker and has no account mutation capability. Local follows open the canonical channel instead of searching its display name.

Public pages show up to 20 normalized records. Next/previous actions replace the displayed page rather than growing the full catalog model indefinitely. Previous-page cursors are bounded to 1,024 and back-navigation locations to 32. Each saved location owns its bounded previous-page cursor stack, so Back restores paging controls for that catalog. The existing model object remains stable; incoming page rows are appended after an explicit navigation reset, and thumbnails still update one existing row and group child. Navigating to the local library or settings retains the bounded guest dataset and releases off-screen thumbnail references.

Channel/playlist type badges, empty-state images, navigation controls and the application badge all use unchanged official Lucide SVGs. A channel card's avatar is displayed with its aspect ratio retained. Thumbnail requests now permit the exact avatar origins `yt3.ggpht.com` and `yt3.googleusercontent.com` alongside the existing exact ytimg hosts; inherited cookies/proxies and redirects remain disabled, and existing compressed/decoded image bounds are preserved.

New fixtures test typed URL routing, preserving channel/playlist kinds without fake VideoSummary values, bounded navigation storage, and exact avatar-host rejection. Provider live checks are recorded in `docs/provider.md`; a native UI capture and real keyboard/selection exercise for this adapter are still pending. This is not a cross-platform or large-catalog performance claim.

These checks compile the shared Slint additions; a native interaction test for these follow-up actions remains pending.

Search recovery correction (source-reviewed during the exclusive soak; not yet compiled or exercised natively): submitting invalid input still cancels the previous worker generation, but retains the acknowledged catalog page and its Next cursor/control. Pasting a video URL likewise preserves that page while extraction runs and if extraction fails; the ordinary worker error handler clears Busy and reports the error without replacing catalog rows. Actual catalog navigation still clears the old page in `load`. There is no existing real-catalog UI diagnostic to extend without adding a new harness: the provider-only `catalog_smoke` cannot prove UI callback behavior. Pending native validation is to load a genuine paginated search, record its IDs, submit invalid input, verify the same IDs and Next control, then use Next to fetch a real continuation. Repeat after a genuinely unavailable pasted video and verify the original page remains navigable. These checks must use real acknowledged cursors, not a synthetic Next-control sentinel.
